# v2 지정 폴더 9개 직계 목록 대조

04:18:37 UTC의 기존 메타데이터 DB와 05:00:17 UTC 변경 범위 보고서에서 비교 대상을 고정한다. 이전 DB ZIP SHA는 `0c0e685a079c68f7ac6c51874d45dc2e5feaad3120cc03cde0a0e3006e03800a`, 05:00 보고 ZIP SHA는 `a7cd85e64e05a750b6bab0b9082a88e4d0ae03cc53f317d28cf6fadae90fe934`다. 변경 17건 중 DB에 있는 RGB 폴더 6개와 pose 폴더 3개가 직계 목록 대상이다. 나머지 7건과 승인 삭제 1건은 별도로 보고한다. 기존 DB의 직계 비교 대상은 합계 220개다.

Worker는 승인된 9개 ID에 대해서만 `files.list`를 호출한다. 폴더별로 직접 들어 있는 항목의 페이지를 끝까지 읽으며 자식 폴더를 추가로 순회하지 않는다. 대상과 부모 체인 및 나머지 7건에는 필요한 `files.get` 메타데이터를 사용한다. API 전체 한도는 128요청·16MiB 응답·240초다. 전체 목록 재조회, 새 변경 토큰 발급, corpus 변경 재조회 및 파일 본문 읽기는 실행 경로에 없다.

현재 직계 목록에는 기존 수집기와 같은 공식 폴더·파일 필터를 적용한다. ID·경로·종류, 비교 근거가 있는 버전·크기·SHA·수정 시각을 확인한다. 추가 및 누락, 이름·종류 변경, 같은 이름의 새 ID 교체, 관측된 다른 대상 폴더로의 이동, 메타데이터 차이를 기록한다. 누락 ID를 다른 직접 목록에서 발견하지 못하면 삭제와 이동을 구분할 수 없다. 원래 제외된 항목은 당시 DB에 남지 않았으므로 현재 존재하더라도 과거 상태는 미확인이다. 현재 부모와 새 경로는 별도 필드로 기록하며 RGB 루트의 비교 부모는 DB가 아닌 05:00 보고서의 이전 변경 사건에서 가져온다.

`report.json`의 `summary`에서 비교 완료 수·경로와 일관성 확인 수, 이전/현재 필터 결과 합계, membership·부모·경로 차이, 비교 가능한 provider SHA 일치·차이·미제공을 확인한다. 미완료 또는 일관성이 확인되지 않은 대상이 있으면 전체 동일 판정은 `null`이다. 동일한 provider SHA는 Drive가 담아준 해시 비교이며 실제 파일 바이트를 새로 검증한 결과는 아니다.

불완전 조회 응답, 토큰 재등장, 목록 내 중복 ID나 부모 불일치는 해당 비교를 중단한다. 대상과 확인한 조상의 현재 메타데이터를 전후로 비교하고 값이 달라지면 결과가 같게 보이더라도 판정은 보류한다. 이 방법은 직계 목록 조회를 한 시점에 고정하지 않으며, metadata가 모든 자식 변경을 반영하는지도 전제하지 않는다. 9개 부분 진단 결과와 전체 corpus 일관성은 별개다.

기타 7건은 현재 대상 폴더의 조상인지, dataset 계층 아래인지, DB에 대응되는 ID가 없는 별도 가지인지 확인한다. 접근이 거부되거나 부모를 검증할 수 없으면 `unknown`을 유지한다. 04:32 회수 ZIP과 05:00 보고 ZIP은 서로 다른 이름·크기·SHA 기준으로 대조한다. 04:32 ZIP의 현재 파일 메타데이터가 맞더라도 이전 보고서에 조상 변경이 포함된 경우 이전 긍정 조건을 통과할 수 없었던 이유를 기록한다. 이 진단은 당시 API 응답을 소급해 재구성하지 않는다.

## 고정본 발급과 회수

새 Git revision의 `SOURCE_REVISION.txt`, 실행 코드, `reference/spec.json`, 공식 split 세 파일을 source ZIP에 넣는다. 05:00 보고 ZIP은 `reference/v2_scope_050017Z_results.zip`으로 넣는다.

```text
python -m scripts.build_v2_metadata_folders --source <source ZIP> --source-sha <SHA256> --revision <40자리 revision> --output <새 폴더>
```

완성한 source ZIP과 04:18 부모 `results.zip`을 Colab `/content`에 준비한다. 노트북 설정의 `VERIFY_ONLY`는 인증 없이 두 ZIP·DB·공식 split·9개 대상을 검증한다. `RUN_DIRECT_COMPARE`는 검증 후 위 진단만 실행하며 기본값은 꺼져 있다.

종료 처리에서 보고와 로그를 ZIP으로 보관해 다운로드를 제시한다. 선택적 Drive 보관은 기존 마운트 경로의 권한과 여유를 읽어 확인한 뒤, 조회 종료 후에만 새 이름으로 복사하고 크기·SHA를 검증한다. 복사 실패 시 로컬 ZIP이 남는다. VM 자체의 강제 종료에는 종료 처리가 보장되지 않는다. 이 자료를 manifest 승인, 원본 DB 변경, 학습 승인에 사용하지 않는다.
