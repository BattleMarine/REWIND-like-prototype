# V1-ACTUAL-001: 실제 입력 감사와 조건부 A100 학습 인계

2026-11-10. 이 시험은 [v1 전체 실행 연결](V1_TRAINING_RUNNER.md)을 실제 자료로 검증하기 위한 인계다. 오케스트레이션이 고정 배포 묶음을 검토한 후 같은 프로젝트의 테스트 세션에 전달한다. 테스트 중 소스·입력 선택·상한을 임의 변경하거나 실패한 학습을 자동 반복하지 않는다.

## 목적과 순서

1. 고정 소스와 입력 ZIP의 해시를 검사하고 별도 Colab 작업 폴더로 복원한다. 이전 v0 출력과 체크포인트를 덮어쓰지 않는다.
2. Drive에 압축 해제된 RGB·pose 경로를 지정한다. 새 train 1,000페어와 기존 validation 2,236페어의 누락·파일 길이를 먼저 확인한다. 호환 raw pack이 있으면 검증 후 재사용한다. `best_e*.pt` 모델은 입력 캐시가 아니다.
3. 선택 자료의 hash·PNG·pose·좌표 변환을 검사하고 raw pack을 만든다. Camera의 proper rotation, 반사된 world basis, `t=-R C`, 단위 환산, stereo 관계와 재투영을 기존 고정식으로 확인한다. 수치 일치는 모델 예측 정확도가 아니다.
4. 시간 관련 필드와 프레임 간 누락, 원본 motion map의 검증 상태를 조사한다. 양쪽 RGB의 GT overlay는 **정답 시각화**로 검토하며 실제 예측으로 표시하지 않는다.
5. 시간·stereo 동기·좌표·영상 정합·원본 motion 검토 근거가 충족됐을 때만 고정 A100 학습 시험을 실행한다. 충족하지 못하면 감사 결과를 회수하고 오케스트레이션이 다음 판단을 한다. 테스트 세션이 JSON의 검증 상태나 hash를 새로 만들어 통과시키지 않는다.

준비 코드는 CPU를 사용하지만, 학습까지 같은 런타임에서 이어갈 예정이면 처음부터 A100 런타임을 선택한다. 런타임 유형을 바꾸면 로컬 캐시가 사라질 수 있다. CPU에서 감사만 수행한다면 결과와 필요한 raw pack을 영구 보관한 뒤 전환하며, 캐시 보관은 사용자가 수행한다. 이번 감사에서 근거 미충족으로 학습이 보류되면 A100을 계속 켜둘 필요는 없다.

## 입력과 해석

- 선택 content SHA256: `48e3c749c7d7710feb7fd61601b7406264837e7a67ceeb4a48787359825cafad`.
- Train: 20개 sequence에서 50프레임씩, 고유 1,000페어. v0의 흩어진 1,000페어와 다른 선택이며 추가 context를 숨겨 포함하지 않는다.
- Validation: 기존 2,236개 키 SHA256 `b4c52d654e772771e553ce887f81f502ea80082e825bab63d02f7c6088ba2dee`. Teacher의 50프레임 구간 평가 coverage는 별도로 보고한다.
- 공식 split의 `test.txt`는 소속 확인용 metadata로만 포함한다. Test RGB/pose를 읽거나 학습·튜닝하지 않는다. Depth도 사용하지 않는다.
- 입력 ZIP은 목록·규격·보정값·과거 manifest만 담는다. 실제 이미지가 포함된 ZIP이 아니다. 고정 spec은 LF 바이트의 hash가 기준이므로 로컬 CRLF 파일로 임의 교체하지 않는다.

기존 JSON 조사본에는 실제 timestamp가 없었다. 공식 명목 25FPS를 실제 측정 timestamp로 바꾸거나 `frame/25`를 검증된 시간으로 생성하지 않는다. 검증 근거가 없다는 결과도 유효한 감사 결과다. 같은 motion 이름 또는 서로 다른 경로만으로 원본 motion 독립성을 입증하지 않는다. 명목 시간·미검증 독립성 조건의 별도 진단 학습이 필요하면 오케스트레이션이 근거와 한계를 검토해 별도 실행으로 결정한다.

## 자원과 중단 기준

고정 준비 후보는 raw source 읽기16GiB, raw pack 디스크12GiB, 작업 버퍼512MiB, worker4, 2시간이다. 감사는 hash 재검사와 member 읽기를 포함한 **로컬 읽기**32GiB, 보고서128MiB, 1시간 이내다. 정확한 실행 인자는 배포 receipt와 notebook을 따른다. OS/Drive 단일 IO는 협조적 timeout 즉시 중단을 보장하지 않으므로 notebook subprocess 상한도 유지한다.

학습은 실제 A100 장치 이름·VRAM 확인 후 각 stage 1epoch: frontend500·body20·hand20, 총540회 순회 update 후보다. FP32·입력128px·frontend batch2·teacher512차원·DDIM10이며 학습 호출2시간, 출력1GiB, 보존 특징128MiB, 체크포인트256MiB 상한이다. 충분한 로컬 디스크를 확인하고 준비와 학습 예산을 구분한다. 이것은 성능 완성 시험이 아닌 데이터·학습 연결 pilot이며, 낮은 정확도만으로 실행 실패로 판정하지 않는다.

누락 파일, source/input hash 불일치, 좌표 검산 실패, 예산 초과, CUDA OOM, 비유한 loss/gradient 또는 근거 미충족이면 결과를 보존하고 중단한다. T4이면 A100 시험을 실행하지 않는다. 설정·데이터·GPU를 바꾸어 같은 실행 이름으로 재시도하지 않는다. 안전하게 저장된 동일 실행 재개는 고정 소스·설정·last SHA에 한한다.

## 회수와 판정

감사 회수에는 준비 진행 상태·누락 목록·cache manifest와 hash·audit 보고서·카메라 후보·시간 필드 조사·검토용 overlay를 포함한다. Raw cache 본체는 결과 ZIP과 별도 보관하고 에이전트가 Drive로 업로드하지 않는다. 사용자 보관이 필요하면 정확한 파일과 위치를 테스트 세션이 안내한다.

학습을 실행했다면 `run.json`, 현재·저장 cursor, `last.pt`, 참조하는 best 모델과 회수 receipt를 회수한다. 실제 GPU·VRAM·학습 설정·검증 coverage·loss/MPJPE·no-supervision batch·준비/학습/평가 wall-clock을 최종 결과에 포함한다. 모델 결과는 프로젝트 문서에도 기록한다.

원본 데이터 검사가 완료됐지만 시간/영상/모션 근거가 남으면 **감사 완료·학습 보류**다. 학습 성공은 모든 stage 종료와 저장 파일 검증·유한 지표로 판정한다. CPU 합성 검사 통과를 실제 데이터/A100 성공으로 보고하지 않는다. 실패 시 코드 수정이나 상한 확대는 테스트 세션이 하지 않고 최종 근거를 오케스트레이션에 전달한다.
