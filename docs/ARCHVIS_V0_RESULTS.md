# ARCHVIS-V0-001 학습 결과와 종료 오류 검토

2026-11-09 root 검토. 동일 train 1,000페어와 공식 validation 2,236페어로 **20 epoch·10,000 update 학습을 완료했다.** Notebook 종료 기록에는 오류가 있었지만 회수된 학습 상태와 결과는 완료를 뒷받침한다. 2D 모델 학습 결과이며 3D REWIND-like v0 완성을 뜻하지 않는다.

## 실행과 보존 근거

- 구현 `1437cdc7829ac7e74852f66ad1b7bec3a0857c0b`, base source `ceb8591a3c2c45549d04f9fda6cab871ecd47ccf`와 별도 v0 overlay.
- 고정 계획 SHA `877f08fb06b8953ff2a675855475b7097519227d7410ce3c9b051a1a0ce3dc94`.
- 회수 ZIP: `outputs/archvis_v0_20261109/user_test/archvis_1000_v0_recovery.zip`, 3,439,558bytes, SHA256 `e27e4f1d13cb7141f4ff53e6ad65de394a6ec496dbde3458ee0086033e6dcac9`.
- 실제 장치는 **Tesla T4**였다. 안내에서 추천한 A100과 다르지만 GPU 최소 자원 gate는 만족했다. FP32, batch2, 64×64, CE, Adam1e-4, seed71, PyTorch2.14.1+cu130, Python3.13.16.

Root는 ZIP CRC·receipt13파일 크기/SHA, 고정 계획·manifest, base/overlay의 모든 기록된 source hash를 대조했다. Last와 best의 모델 tensor가 같고 유한하며, optimizer tensor·scheduler 상태, epoch20/step10000/samples20000/attempts10000/skip0/nonzero-gradient10000을 확인했다. Epoch마다 고유 train1,000페어를 처리했고 초기/1/5/10/15/20epoch 평가가 모두 있다. Best는 epoch20이다. 이 검토는 실제 GPU에서 중단·재개 동등성을 새로 시험했다는 의미가 아니다.

근거와 추출한 예측은 `outputs/archvis_v0_20261109/user_test/root_review/`에 보존했다. 이전 런타임의 소실된 시도는 확인할 수 없으며 이번 회수 실행과 구분한다. Drive 영구 보관 여부는 아직 확인되지 않았다.

## 정확도

Native 1024px 좌표의 Euclidean 거리이며, 좌우 영상의 유효 관절 관측을 합산한 평균이다. Best 선택은 화면 안 whole 관절 오차를 사용한다. 화면 밖 관절은 아래 전체 유효 관절 지표에 포함한다.

| 초기 | 335.290 | 360.182 | 7.0123 |
| 1 | 308.933 | 333.663 | 6.7343 |
| 5 | 234.247 | 255.871 | 6.1672 |

화면 안 오차는 초기보다 약41.7% 감소했고 중앙 고정 baseline335.258px보다 낮다. 최종 화면 안 몸22관절 오차는121.159px, 손40관절은242.988px다. 전체 유효 관절에서는 몸124.428px·손269.915px다. 손 정확도가 특히 낮고 화면 밖 whole 오차도415.441px로 크다. Epoch 평균 train CE는6.8615→5.5286으로 감소했다.

이전 tiny 모델의 CE 1epoch 화면 안334.707px보다 새 모델의 같은500update 결과308.933px가 낮다. 단, GPU·소프트웨어 환경이 달라 엄밀한 동일 환경 비교는 아니다. 20epoch와 이전1epoch 차이를 모델 구조 단독 효과로 해석하지 않는다.

Root가 회수된 대표 validation3페어의 왼쪽 overlay를 확인했다. 점들이 단일 중앙 위치에서 벗어나 몸·손 형태로 분포하지만 실제 영상의 관절 위치와 어긋나는 부분이 많다. 64px 입력을 확대한 표시이며 전체 validation의 시각 검토는 아니다. 원본 motion 독립성·실제 RGB-pose 시각/시간 정합은 미완료다. Validation 개선은 확인했지만 과적합이 없거나 높은 일반화 정확도를 얻었다고 결론내리지 않는다.

학습 처리량의 분모는 **1,000×20=20,000페어 처리**다. 캐시 생성의 분모는 train+validation의 고유3,236페어이며 약1.431초/페어다. 전체 시간의 약92%가 캐시 생성에 쓰였다. 여기에는 원본 파일 읽기·hash·PNG decode·resize·로컬 저장이 함께 들어 있으므로 모두 네트워크 전송 시간이라고 단정하지 않는다. 학습 시간에도 캐시 읽기·hash·역직렬화·GPU 연산이 포함되며 순수 GPU kernel 시간이 아니다. Mount·업로드·사용자 대기·결과 다운로드와 소실된 이전 시도는 제외한다.

원본 예약 읽기는7,565,245,379bytes이며 순수 네트워크 전송량이 아니다. 캐시 논리 크기는332,607,444bytes(약317.2MiB), 관측 RSS peak약1.83GiB, Torch allocated약9.31MiB/reserved30MiB였다. Torch 수치를 전체 VRAM 사용량으로 해석하지 않는다. 모든 보고 자원은 고정 상한 이내였다.

동일 모델·T4·캐시 조건에서 ArchVis train20,888을20epoch 학습하는 **학습 구간만** 선형 추정하면 약99분이다. 반면 이번 준비 속도를 전체 train+validation23,124페어에 적용하면 약9.19시간, 캐시 논리 크기는약2.21GiB다. 파일 크기·Drive 상태·캐시 조건에 따라 달라지는 조건부 추정이다. 현재384MiB 캐시·2시간·고정1,000페어 실행본으로 전체 학습을 바로 실행할 수 없으며, 이 계산은 전체 실행을 시작한 것이 아니다.

## 종료 기록 오류

실행 wrapper가 시작 시 `v0_launch.json`을 만든 뒤 종료 시에도 신규 파일 전용 `pilot._write`(`open("xb")`)를 호출했다. 따라서 이미 있는 파일에 쓰려다 `FileExistsError`가 발생했다. 시작 기록이 `started`로 남고 종료 returncode 기록이 유실됐으며, `finally`의 오류가 앞선 예외를 가렸을 가능성도 있다.

회수 보고서의 `completed`, 마지막 epoch/update와 best/last 상태는 실제 학습 완료 근거다. 그러나 child returncode 자체는 이번 자료만으로 확정하지 않는다. 오류는 종료 기록 경로에서 수정하며, **이 오류를 확인하기 위해 학습을 다시 실행하지 않는다.** 기존 고정 notebook과 회수본은 보존한다. 후속 builder는 종료 JSON을 임시 파일에 쓴 뒤 원자적으로 교체하도록 수정했다. 생성된 notebook 셀에서 성공·프로세스 실패·timeout·사용자 중단·진단 저장 실패의5개 검사를 root가 통과시켰고, 원래 프로세스 예외가 보존됨을 확인했다. 수정본의 새 GPU 실행은 하지 않았다.
