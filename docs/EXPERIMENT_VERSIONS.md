## v1.5의 현재 범위 — 2026-11-15 재정의

사용자가 카메라 표현 통제 학습을 v1.5의 주실험으로 확정하고 진행을 승인했다. v1.6에서 제안한 학습·추론의 공통 원점 기준, causal anchor 보존, 같은 조건의 비교 평가를 흡수한다. 별도 v1.6은 폐기하며 실행 번호로 사용하지 않는다.

1. 주실험: 기존 absolute camera와 첫 프레임 stereo 중점 기준 camera를 학습·추론에 각각 일관되게 적용한다. Frontend·예측2D·hand 상체 학습 정책·초기 state·학습량 등은 고정한다.
2. 평가: ArchVis·도시의 body/hand 오차·형태와 원점 이동 안정성을 함께 비교한다. 기존 6클립은 개발·회귀 표본이며 독립 일반화 근거로 호칭하지 않는다.
3. 조건부 후속: 잔여 손·몸 오류에 따라 GT/예측 상체 또는 2D를 분리 진단한다. 기존 단일클립 A/B/C를 이번 주실험과 함께 자동 실행하지 않는다.

구체적인 입력·초기화·update·LR·예산·중단/복원과 배포 pin은 전용 실행 계약에서 고정한다. 진행 승인은 실제 학습이나 정확도 개선 완료가 아니다.

구체적인 입력·학습량·평가·복원 계약은 [v1.5 실행 설계](V15_CAMERA_TRAINING.md)를 따른다.

## v1.5의 초기 설계 — 보존 기록

부모 질문은 v1.4의 정답 조건 복원 성공과 v1.2의 예측 조건 오류 사이의 차이다. 같은 Standing_Up 50프레임에서 frontend를 고정하고 다음 조건을 비교하는 제안이다.

| 기존 실험군 | 2D 조건 | Hand 학습 상체 | 구분하려는 효과 |
| --- | --- | --- | --- |
| A | GT | GT | 정답 조건 대조군 |
| B | 고정 frontend 예측 | GT | GT와 예측2D 특징의 차이 |
| C, 조건부 후속 | B와 같은 예측 | B body의 고정 예측 | Hand 학습·추론 상체 조건 불일치 |

동일 초기 state·update·noise 비교와 카메라 조건 고정이 전제다. 기존 A/B/C 명칭을 camera 실험군에 재사용하면 의미가 충돌한다. 이전 대화의 ‘v1.5-A 카메라 표현 / v1.5-B GT·예측 조건’은 미확정 제안이며 이 기존 설계를 변경한 결정으로 취급하지 않는다.

## 과거 번호 제안 — v1.6은 폐기되어 v1.5에 흡수

아래는 재정의 전 비교·권고의 보존 기록이다. 현재 결정은 위의 v1.5이며, 아래 미확정·권고 표현을 현행 실행 지시로 해석하지 않는다.

현재 우선하고 싶은 질문은 **학습과 추론에 같은 원점 기준을 적용하면 원점 민감도와 도시 붕괴가 줄고 ArchVis·손 성능도 유지되는가**다. 이는 v1.5의 GT/예측 조건 분리와 변경 변수가 다르다.

| 항목 | 기존 v1.5 | 새 카메라 표현 시험 제안 |
| --- | --- | --- |
| 직접 근거 | v1.4 oracle와 예측 조건의 격차 | v1.2.3 원점 개입 결과 |
| 변경 변수 | 2D·상체의 GT/예측 조건 | Camera translation의 절대/기준 원점 표현 |
| 데이터 후보 | 같은 한 클립 50프레임 | 같은 연속 구간 1,000페어에서 소규모 비교 후 확대 검토 |
| 고정할 것 | 카메라 표현, 초기화·update 등 | Frontend·2D 특징·상체 조건 정책·데이터·초기화·update 등 |
| 주 판정 | 입력 조건별 복원 차이 | 원점 이동 안정성, body·hand 정확도와 형태 |

**권고 번호는 v1.6**이다. v1.5는 기존 뜻으로 보존하고 필요할 때 후속 수행한다. 번호는 실행 순서가 아니므로 v1.5보다 v1.6을 먼저 실행할 수 있다. 이번 사용자 요청은 번호·범위 검토이며 v1.6 확정이나 새 학습 승인이 아니다.

새 시험에서는 원본 절대 translation과 첫 프레임 stereo 중점 기준 translation의 두 학습군을 비교하는 안이 적합하다. Frontend는 고정해 특징을 재사용하고, body·hand의 학습 조건은 카메라 표현 외에 바꾸지 않는다. 특히 camera 효과를 보는 동안 hand의 GT상체 학습 정책까지 동시에 변경하지 않는다.

실행 전에는 동일 초기화의 종류(새 초기화 또는 같은 기존 checkpoint), 선정 manifest, update/LR·예산, clip/sequence/streaming의 원점 초기화·재개 보존 규칙, body·손 허용 기준을 확정해야 한다. 1,000페어는 비용을 줄이기 위한 후보이며 사용자 확정 규모가 아니다. 기존 6클립은 회귀·원점 민감도 확인용으로 쓰고, 독립 일반화에는 별도 미사용 표본이 필요하다.

다른 선택으로 v1.5를 새 카메라 시험으로 명시 재정의할 수는 있다. 다만 그 경우 기존 GT/예측 조건 설계의 새 이름과 이전 명칭 대응도 함께 정해야 한다. 같은 번호에 두 목적을 병존시키지 않는 것이 중요하다.
