# v1.2 및 세 파생 시험 종합 분석 보고서

작성일: 2026-11-15 · 대상: REWIND-like prototype · 상태: 실제 결과 검토 완료, 후속 실험은 제안

## 1. 종합 결론

**v1.2는 학습한 ArchVis 환경에서 몸 형태를 복원하는 능력을 얻었지만, 카메라의 절대 world 원점에 크게 의존했다. 이 의존성은 CityPark·Downtown의 큰 위치 편향과 몸 축소를 유발하는 주요 기여 요인으로 확인됐다.** 따라서 다음 개선의 우선순위는 데이터나 epoch를 무조건 늘리는 것보다 학습·추론에서 사용하는 카메라 좌표 표현을 일관되게 정리하는 데 있다.

근거는 세 단계로 강화됐다. 먼저 도시 전이 평가에서 실패를 관찰했고, 같은 추론 경로의 ArchVis 대조에서 환경별 차이를 확인했다. 마지막으로 이미지·모델·예측2D·정답을 그대로 두고 좌표 원점만 이동시켰을 때 도시의 body 오차가 크게 줄었으며, 반대로 ArchVis에서는 몸 축소가 재현됐다. 이는 단순한 환경 간 상관관찰을 넘어선 입력 조건 개입의 결과다.

다만 **원점 정렬만으로 해결됐다는 결론은 이르다.** ArchVis 손 정확도는 오히려 악화했고, 도시에서도 자세·손 오류가 남았다. 세 파생 시험은 같은 인물 경로의 고정 6클립·300프레임을 이용한 진단이며, 새로운 모델의 학습 성공이나 다양한 인물·동작에 대한 일반화 입증은 아니다.

## 2. 시험의 분기와 목적

```text
v1.2 — ArchVis 전체 train으로 학습 확대
│       질문: 학습 신호와 데이터 노출을 늘리면 형태가 복원되는가?
│       결과: 2D·body 개선, 손 축소·자세 오차 잔존
│
└─ 파생 1: V12-CROSS-SCENARIO-001
   │       질문: 같은 모델이 CityPark·Downtown에서도 동작하는가?
   │       결과: 큰 위치 편향과 몸 축소, 원인 미확정
   │
   └─ 파생 2: V12-CAMERA-CONTROL-001
      │       질문: 같은 추론 경로의 ArchVis도 실패하는가?
      │             환경별 카메라 조건에는 어떤 차이가 있는가?
      │       결과: ArchVis 몸 크기 유지, translation 조건의 큰 차이 확인
      │
      └─ 파생 3: V12-CAMERA-GAUGE-001
                  질문: 물리적으로 같은 장면의 원점만 바꾸면 예측이 변하는가?
                  결과: 큰 민감도 확인, 도시 개선·ArchVis 역방향 악화 재현
```

여기서 ‘파생 1~3’은 설명을 위한 시험 순서다. 새로운 학습 모델 세 개를 만들었다는 뜻이 아니다. **세 시험 모두 고정된 v1.2 모델을 재학습 없이 사용했다.** 시험 2는 기존 도시 예측을 재사용했고, 시험 3은 같은 6클립을 다시 추론했다. 따라서 200+100+300을 서로 독립인 600개 표본으로 합산하면 안 된다.

| 구분 | 학습 또는 평가 범위 | 변경·통제 | 검증 목적 |
| --- | --- | --- | --- |
| v1.2 본 학습 | ArchVis train 20,888페어; frontend/body/hand 각 10epoch | v1.1보다 데이터·update 증가 | 학습 확대 후 복원 능력 확인 |
| 파생 1 | CityPark 100 + Downtown 100프레임 | 모델 고정, 평가 환경 변경 | 다른 환경에서의 실패 양상 확인 |
| 파생 2 | ArchVis 100프레임 추가 평가; 총 300행 camera 비교 | 같은 모델·추론 경로; 기존 도시 예측 재사용 | 공통 경로 문제와 환경 조건 차이 구분 |
| 파생 3 | 같은 6클립·300프레임 | RGB·2D·GT·회전·noise 고정, 원점만 변경 | 원점 조건의 직접적인 영향 확인 |

파생 시험은 모두 공식 validation에서 선정한 환경별 2개 연속 50프레임 클립이다. ArchVis는 Standing/Petting Animal, CityPark는 Gunplay/Kneeling Inspecting, Downtown은 Reloading/Quarterback Pass다. 시나리오 전체를 대표하도록 무작위 추출한 대규모 표본은 아니다.

## 3. 모델·입력·지표의 공통 기준

후속 평가 모델은 frontend epoch 9, body epoch 10, hand epoch 9의 고정 checkpoint다. RGB에서 예측한 2D 특징과 pose JSON의 카메라 metadata를 body에 제공하고, hand에는 예측 body 상체와 wrist 조건을 제공한다. GT 관절은 평가·기하 검사·시각화에만 사용했다. **카메라 metadata까지 RGB에서 추정하는 완결된 RGB-only 시스템은 아니다.**

세 파생 시험은 CUDA FP32, DDIM 10step, seed 71, body/hand noise offset 100/200, 클립별 상태 초기화를 유지했다. 실제 장치는 A100-SXM4-40GB, torch 2.14.1+cu130이었다. 명목 25FPS와 frame-key stereo 대응 가정은 유지하되 실제 timestamp·동기·원본 motion 독립성은 미확인이다.

| 지표 | 의미와 주의사항 |
| --- | --- |
| 2D 오차 | 원본 이미지 좌표의 px. 전체 유효 관절과 화면 안 관절의 mask가 다르므로 구분한다. |
| Body MPJPE | Device 기준 몸 22관절의 평균 3D 거리 오차(mm). 중심·회전·scale 정렬로 위치 오류를 제거한 지표가 아니다. |
| Hand global | Device 기준 손 40관절의 3D 오차. 예측 wrist 위치 영향이 포함된다. |
| Hand local | Wrist를 기준으로 한 손의 상대 관절 오차. Global 평균에서 빼서 wrist 오차를 계산할 수 없다. |
| 평균 뼈 길이·spread | 예측 형태가 점처럼 축소됐는지 확인하는 보조 지표. 정상 크기가 정확한 자세를 보장하지 않는다. |
| Body centroid 오차 | 예측과 GT 몸 중심의 거리. 전체 위치 편향을 확인한다. |

본 학습의 validation best와 파생 시험의 고정 클립 점수는 평가 표본·집계 범위가 다르다. 같은 지표 이름이라도 하나의 순위표로 섞어 모델이 더 좋아졌거나 나빠졌다고 해석하지 않는다.

## 4. v1.2 본 학습: 무엇을 얻었는가

Train 20,888페어, frontend validation 2,236페어로 각 10epoch를 완료했다. Teacher train은 564클립, validation은 29클립·1,450프레임이며 validation 786프레임은 제외됐다. 총 update는 115,720회다.

| 참고 validation 지표 | v1.1 | v1.2 | 해석 |
| --- | ---: | ---: | --- |
| 2D 화면 안 오차(px) |214.84|89.97|2D 조건 품질 개선 |
| Body MPJPE(mm) |484.79|169.56|몸 복원 개선 |
| Hand global MPJPE(mm) |514.85|318.56|개선됐지만 잔여 오차 큼 |
| Hand local, global best 시점(mm) |124.67|100.91|손의 상대 형태 개선은 제한적 |

v1.2 body 평균 뼈 길이는 예측 184.76/GT 208.35mm로 극단적인 축소에서 벗어났다. 반면 손 뼈 길이는 14.54/25.78mm로 축소가 남았다. 별도의 train 2프레임 시각화에서도 몸 형태가 펴졌지만 사지 방향과 손 위치 오류가 보였다. 이 시각화는 T=1 reset이며 연속 validation 평가와 구분한다.

**판단:** 모델이 전혀 학습하지 못하는 상태는 아니다. 그러나 v1.1 대비 데이터뿐 아니라 frontend update 5,000→104,440회, 각 teacher 200→5,640회, GPU와 short/tail 처리도 함께 달라졌다. 개선을 데이터 양 하나의 효과로 확정할 수 없다. [본 학습 상세](V12_TRAINING_RESULTS.md).

## 5. 파생 1: 도시 전이에서 발견한 실패

| 환경 | 2D 전체 유효(px) | Body(mm) | Hand global(mm) | Hand local(mm) |
| --- | ---: | ---: | ---: | ---: |
| CityPark, 100프레임 |307.87|6,721.67|7,524.48|3,145.50|
| Downtown, 100프레임 |334.31|2,277.83|2,912.33|1,188.49|
| 합계 200프레임 |321.09|4,499.75|5,218.41|2,166.99|

Body 평균 뼈 길이는 예측 16.70/GT 185.28mm, 약 9%에 불과했다. 평균 body 중심 오차는 4,477.52mm였고, 중심을 각각 제거한 후의 오차도 373.74mm였다. 즉 **위치 이탈과 형태 축소가 함께 발생**했다. 그림의 축척 문제만으로 설명할 수 없다.

이 단계에서는 영상·동작·2D 품질·카메라 조건이 동시에 달랐으므로 원인을 특정할 수 없었다. GT·카메라 내부 기하와 full50/prefix25 검사는 통과했지만, 내부 일관성 검사는 모델의 입력 분포 적합성이나 예측 정확도를 보장하지 않는다. [도시 평가 상세](V12_CROSS_SCENARIO_RESULTS.md).

## 6. 파생 2: ArchVis 대조와 카메라 조건 차이

같은 연속 추론 경로로 ArchVis 100프레임을 평가했다. Body 197.34mm, 예측 뼈 길이 184.87/GT 185.28mm로 도시와 달리 몸 크기를 유지했다. 따라서 ‘이 추론 경로는 어떤 입력에서도 몸을 붕괴시킨다’는 설명은 관찰과 맞지 않는다. 다만 모든 공통 구현 오류를 배제한 것은 아니다.

| 환경 | Body(mm) | 예측 body 뼈 길이(mm) | 양쪽 camera translation norm 범위(m) |
| --- | ---: | ---: | ---: |
| ArchVis |197.34|184.87|1.66~3.53|
| CityPark |6,721.67|14.67|262.14~270.40|
| Downtown |2,277.83|18.73|58.71~129.70|

이 norm은 **카메라와 사람 사이의 거리나 depth가 아니다.** World 원점에 의존하는 world→camera translation의 크기다. 모델에는 translation을 100mm로 나눈 성분이 입력된다. Device 기준 인체가 비슷해도 world 원점이 다르면 입력 수치가 크게 달라질 수 있다.

도시 translation 성분의 대부분은 이번 ArchVis 100프레임의 min/max 밖에 있었다. 이는 평가 표본 간 차이이며, 전체 train 카메라 분포를 감사하거나 공식 OOD 경계를 확정한 것은 아니다. **이 단계는 원점 의존성을 우선 가설로 올린 상관 근거**다. [대조·분포 상세](V12_CAMERA_CONTROL_RESULTS.md).

## 7. 파생 3: 원점만 바꾼 직접 개입

World 좌표를 `x′ = x + Δ`로 바꾸면 동일한 카메라 공간을 유지하려면 `t′ = t − RΔ`가 된다. 클립의 모든 프레임과 좌우 카메라에 같은 Δ를 적용했다. 회전, stereo 상대기하, RGB, 예측2D, device GT, 모델, noise는 바꾸지 않았다.

네 조건은 원본, 원본 반복, 첫 프레임의 stereo 카메라 중점을 원점으로 이동, 고정 canonical world x축 +100m 이동이다. 첫 프레임의 camera만으로 Δ를 정했으며 미래 프레임이나 GT 오차로 조정하지 않았다.

### Body 결과

| 환경 | 원본(mm) | 중점 원점(mm) | +100m(mm) | 핵심 관찰 |
| --- | ---: | ---: | ---: | --- |
| ArchVis |197.34|180.50|2,173.84|원점 이동만으로 큰 오류와 축소 재현 |
| CityPark |6,721.67|276.27|8,023.31|중점 원점에서 큰 위치 편향 완화 |
| Downtown |2,277.83|306.05|2,283.11|중점 원점에서 개선, 임의 이동은 개선 보장 없음 |

CityPark 뼈 길이는 14.67→166.46mm, Downtown은 18.73→162.04mm로 회복됐다. 두 환경의 GT 평균은 185.28mm다. Body 중심 오차도 각각 6,715.69→181.33mm, 2,239.34→199.43mm로 줄었다. 반대로 ArchVis +100m의 뼈 길이는 18.01mm로 축소됐다.

### 손 결과와 해결책의 한계

| 환경 | Hand global 원본→중점(mm) | Hand local 원본→중점(mm) |
| --- | ---: | ---: |
| ArchVis |293.29→319.78|82.15→165.44|
| CityPark |7,524.48→579.47|3,145.50→302.63|
| Downtown |2,912.33→377.02|1,188.49→139.71|

도시의 손도 개선됐지만 ArchVis 손은 악화했다. 따라서 ‘추론 때 중점을 빼면 모든 문제가 해결된다’는 정책으로 바로 전환할 근거는 부족하다. 기존 학습 표현과 추론 표현의 차이, hand에 전달되는 body/wrist, hand 모델 자체의 camera 의존성을 분리할 필요가 있다.

### 결과의 신뢰도

원본 예측은 이전 결과와 정확히 일치했고, 같은 실행의 원본 반복도 최대차이 0mm였다. 저장된 기하의 float64 불변 잔차는 약 1.2e-10mm 이하, float32 translation roundtrip 최대 0.01215mm, camera-space 약 0.02394mm, 상대stereo 약 0.03021mm였다. 양자화는 완전히 0이 아니지만 수천mm의 예측 변화와 몸 축소는 미세한 반복 오차 수준이 아니다.

이로써 **현재 모델이 물리적으로 같은 장면의 world 원점 재표현에 크게 민감하다는 사실**을 확인했다. 도시 실패의 주요 기여 요인으로 camera translation 표현을 지목할 근거도 강해졌다. 모든 잔여 오차의 원인, 특정 네트워크 층의 내부 메커니즘, 새 표현으로 학습한 모델의 성능까지 입증한 것은 아니다. [개입 시험 상세](V12_CAMERA_GAUGE_RESULTS.md).

## 8. 원인에 대한 최종 판단

| 설명 또는 가설 | 현재 판단 | 근거와 남은 한계 |
| --- | --- | --- |
| 모델이 학습 자체를 못 했다 | 전체 설명으로 부적절 | ArchVis 학습·연속 대조에서 몸 크기 복원 확인 |
| 도시 실패는 학습량 부족만의 문제다 | 단독 설명으로 부족 | 가중치를 바꾸지 않고 camera 원점만으로 큰 변화 발생 |
| 절대 world 원점 조건이 큰 실패 요인이다 | 이번 표본에서 강한 개입 근거 | 도시 개선 및 ArchVis 역방향 실패 재현 |
| 2D 예측 오류가 3D 실패의 유일한 원인이다 | 단독 설명으로 부족 | 동일한 잘못된 2D에서도 camera 변경으로 3D 크게 개선 |
| 2D 오류는 더 이상 중요하지 않다 | 근거 없음 | 도시 2D 오차는 그대로이고 잔여 자세·손 오차 존재 |
| 원점 정렬만으로 최종 해결됐다 | 부정 | ArchVis 손 악화, 다른 인물·동작 미검증 |
| 도시 데이터를 섞으면 자동으로 해결된다 | 아직 미검증 | 혼합학습 미실행; 잘못된 원점 의존성을 그대로 학습할 수도 있음 |

이는 논문 구조 자체의 실패 판정이 아니라 **현재 프로젝트 구현·조건 표현·학습 모델에 대한 진단**이다. 이번 시험으로 REWIND 공식 구현과의 동등성이나 논문 성능 재현을 평가하지 않았다.

## 9. 권고하는 다음 단계

**우선순위 1은 학습과 추론에서 같은 원점 기준을 쓰는 camera 표현의 통제 실험 설계다.** 다음 내용은 제안이며 새 구현·학습 승인을 뜻하지 않는다.

1. 후보 표현을 고정한다. 우선 후보는 첫 프레임 stereo 중점 기준 translation이며, 미래 정보 없이 시퀀스 시작 시 정하고 유지한다. Rotation 전체를 없애거나 camera 정보를 모두 제거하는 것과 구분한다.
2. Clip 경계, 실제 sequence 시작, 스트리밍·중단 재개에서 기준 원점을 언제 초기화하고 어떻게 보존할지 명시한다. 학습 clip마다 다른 기준을 쓰면서 영상 추론에서는 임의로 이어 붙이는 불일치를 피한다.
3. 원본 표현과 변경 표현을 같은 데이터·초기화·학습 update·평가 클립·noise 조건으로 비교한다. 추론만 보정한 현재 진단과, 해당 표현으로 다시 학습한 결과를 별도 실험으로 기록한다.
4. Body뿐 아니라 hand local/global, 뼈 길이, centroid와 2D 지표를 함께 판정한다. ArchVis 손 악화를 감추는 단일 body 평균만으로 채택하지 않는다.
5. 표현 변경 후에도 남는 손 오차는 기존 v1.5 제안의 GT/예측2D·상체 조건 분리와 연결해 조사한다. v1.5의 기존 목적을 새 근거 없이 삭제하거나 자동 대체하지 않는다.
6. 표현 안정성이 확인된 뒤 별도 인물·동작의 미사용 평가와 v1.3 혼합학습을 검토한다. 현재 6클립은 이미 진단·설계에 사용했으므로 향후 독립 일반화 성능의 유일한 근거로 삼지 않는다.

다음 실험의 데이터 규모·budget·학습 설정·손 성능 허용 기준은 실행 전에 별도로 확정해야 한다. 이번 보고서는 그 실행을 자동 시작하지 않는다.
