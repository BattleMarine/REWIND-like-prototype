## 세 GPU에서 독립 학습하는 128 기준 모델

2026-11-22 사용자 승인. 세 Colab에서 같은 읽기 전용 128 캐시를 사용해 seed 42(A), 71(B), 103(C)를 각각 새로 학습한다. 각 seed는 frontend·body·hand를 각각 3 epoch 학습하며 한 세트의 모델과 재개 기록을 보관한다. 공식 train 119,586페어·3,097클립, validation 16,425페어·421클립이며 계획 업데이트는 seed당 197,961회다. A에서 첫 실제 학습 업데이트와 Drive checkpoint 보관을 확인한 후 B와 C를 시작한다. 첫 업데이트는 본학습에 포함한다. 아래의 단일 seed·1 epoch는 초기 제안이다.

실제 제공된 CUDA GPU를 사용하고 장치명·메모리·학습 시간·precision을 결과에 기록한다. 하드웨어가 다르면 seed와 수치 연산 차이의 효과가 섞일 수 있다. 세션별 복원·체크포인트·결과·쓰기 잠금은 분리하고, 현재 운영 중인 256 캐시에는 접근하지 않는다. 공통 validation과 추론 노이즈에서 각 세트의 시나리오별 body·hand global MPJPE를 동일 비중으로 비교하고 hand local 오차, 몸·손 뼈 길이와 자세 영상을 확인한다. 세 seed 전체의 점수와 범위를 보존한다. 장치별 속도는 별도로 보고한다.

## 2026-11-22 · 128 캐시 기반 첫 GPU 학습 제안

**목표**는 ArchVis·CityPark·Downtown의 동일 128 입력으로 frontend와 body/hand teacher를 학습하고, 시나리오별 validation의 실제 예측을 v1.2와 비교하는 것이다. 256 캐싱은 별도 CPU에서 계속 진행한다. 이번 작업은 계획 수립이며 GPU 실행과 누적 GPU 예산은 미확정이다.

1. **입력 고정.** 목표에 도달한 1,063개 샤드의 마지막 경계는 `dc79219153d69f44020e0c42f9f3ede6cd3add179211f6c300345b2416dab511`이다. [공식 split 대조](V2_INPUT_PRODUCTION.md)에 따라 학습 119,586페어와 validation 16,425페어를 분리한다. manifest로 시나리오별 프레임 수·연속 클립 수·padding mask를 산출해 저장한다. Test는 설정 선택에서 제외한다.
2. **GPU 로더 연결.** 보관 캐시를 학습 로더의 읽기 전용 카탈로그에 연결한다. 첫 샤드 원래 위치와 마지막 75페어, 샤드 경계를 넘는 연속 클립을 확인한다. 학습 진입점의 기존 12GiB 캐시·8GiB 읽기·256MiB 특징 저장 한도와 실제 로컬 공간을 대조한다. 전체 복원 또는 제한된 로컬 샤드 재사용 방식의 디스크·I/O 비용을 비교해 결정한다. CPU 캐시 생성 예산과 GPU 학습 예산을 별도로 관리한다.
3. **짧은 실제 업데이트와 재개.** 지원 CUDA GPU에서 실제 학습 배치로 forward/backward·유효 관절 수·유한 loss/gradient·optimizer 업데이트를 확인한다. 체크포인트를 Drive에 보관하고 해시와 복원 후 다음 update 위치를 확인한다. 가능하면 본학습과 같은 설정으로 같은 호출에서 이어 간다. GPU 종류·VRAM, 복원 시간과 학습/검증/특징 생성 속도를 따로 기록한다.
4. **첫 기준 모델.** 현재 구현이 지원하는 신규 초기화, 고정 seed(제안 42), 기존 v1.2 optimizer·학습률·batch 설정을 출발점으로 한다. Frontend를 학습하고 validation으로 선택한 가중치를 동결해 예측 2D 특징을 생성한다. Body teacher, hand teacher 순서로 학습한다. 손 모델은 학습 시 GT 상체, validation과 시연 시 예측 상체를 쓴다. 첫 측정 목표는 각 단계 1 epoch이며 frontend만 batch 2 기준 59,793 update다. GPU 호출당 8시간 안에 저장·종료하고 실측으로 전체 GPU 시간과 추가 epoch 수를 결정한다. 세 단계 1 epoch 완주는 모델 수렴 기준과 별개다.
5. **판정과 결과.** 공식 validation에서 시나리오별 2D 픽셀 오차(같은 좌표 척도), body/hand global·hand local MPJPE(mm), 표본 수와 집계 방식을 기록한다. 사전 고정한 연속 클립으로 RGB/예측2D/GT 및 예측3D를 시각화한다. v1.2 비교는 동일 프레임·관절 mask·추론 조건에서 수행한다. 명목 25FPS와 원본 motion 독립성의 한계는 유지한다. 256 해상도 비교와 student 증류는 후속 단계로 둔다.

첫 산출물은 전체 캐시를 소비하는 학습용 고정 노트북, 학습 설정 및 예산표다. GPU 실측 이후에 학습 시간과 장기 보관량을 갱신한다. [기존 v2 실행 계약](V2_INFRASTRUCTURE.md) · [v1.2 기준 결과](V12_TRAINING_RESULTS.md)

## 범위와 계보

ArchVisInterior_ArchVis_RT·CityPark_Showcase·DowntownWest_Demo_Environment의 RGB·pose 추출본 전체 train으로 frontend/body/hand 통합 모델을 준비한다. 공식 validation은 시나리오별로 평가하고 test는 설정 선택에 사용하지 않는다. 기존 v1.3 혼합학습 제안은 v2로 확대·이관하며 별도 v1.3 실행은 하지 않는다. v1.2 전체 학습 경로와 v1.5 중점 카메라 표현, v1.5.2/1.5.3 진단 결과를 설계 근거로 사용한다. 번호 상승은 논문 성능 재현·완성 선언이 아니다.

기존 실험 manifest·checkpoint는 보존한다. 초기화(새 학습/기존 모델 활용), 학습량, GT/예측 상체 학습 정책과 평가 조건은 구현 전 명시한다. 예측 상체를 사용하는 실제 추론 경로와 시나리오별 평가를 포함할 계획이다. 단일클립 성공을 전체 데이터 수렴으로 외삽하지 않는다.

## 시간 상한 — 후속 사용자 확정

캐싱·입력 준비와 GPU 학습의 1회 전체 상한을 각각28,800초(8시간)로 확정한다. 중간 동기화도 포함하며, 내부에 종료1,320초(package600·copy/readback600·checkpoint120)를 예약해 계산/중간보존 구간은최대27,480초(7시간38분)다. 외부worker timeout28,920초 이후SIGINT60초/kill-wait30초로 제한한다. 같은VM의연속16시간이나18시간을승인·보장하지 않는다. 사용한VM시간도고려한다. 남은 캐싱에는 위의 90시간·60GiB를 적용한다. GPU 학습의 누적 예산은 미정이다.

v1.2 A100 본학습 호출 합계는 약3시간5분이며 준비·복원·최종 보관 전체 시간 또는 순수 GPU 시간은 아니다. 감사에는6시간 상한 중 KeyboardInterrupt로 종료된 사례도 있었다. 상한 확대만으로 연결·VM 종료를 해결하지 못한다. [학습 실측](V12_TRAINING_RESULTS.md) · [감사·재개 근거](V12_AUDIT_RESUME.md).

Colab은 가용성과 사용량에 따라 수명이 달라진다. 공식 FAQ는 무료 최대12시간, 충분한 compute units가 있는 Pro+ 연속 실행 최대24시간을 안내하나 일정 실행시간을 보장하지 않는다. [공식 FAQ](https://research.google.com/colaboratory/faq.html).

전체 누적 비용은 정리 후 split별 사용 가능 프레임·연속클립 수, GPU·IO 실측, 학습량을 바탕으로 별도 산출한다. 정리 전 train_val 파일 수를 실제 train 수로 취급하지 않는다. 시간 상한 외 전송·RAM·디스크 상한은 독립적으로 산정한다.

## 준비 작업

1. 세 시나리오 공식 split과 추출본을 대조해 사용 가능한 train/validation 목록·클립·크기를 산출한다.
2. 기존 v1.2의 감사·캐시·학습 재개 경로를 검토하고, v2 입력 identity와 중점 카메라 표현을 연결한다.
3. 완료 캐시 구간과 checkpoint를 주기적으로 Drive에 보존할 방식을 준비한다. 전체 캐시 반복 복사 대신 완료 shard 단위 보관·검증을 검토하며 원본/캐시 업로드는 기존 사용자 담당 규칙을 따른다. 마지막 셀만의 보관에 의존하지 않는다.
4. 실제 GPU 종류를 제한하지 않고 실행 전 비용·남은 디스크·중단/재개 조건을 고정한다. 새 VM 복원 지원은 기존 지원 범위를 점검한 후 검증한다.
5. 구현·root 검토·고정 revision/노트북 준비 후 테스트 세션에 인계한다. 이번 명명과 시간 권고로 원격 대규모 작업을 자동 시작하지 않는다.
