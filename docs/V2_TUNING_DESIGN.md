# v2 베이스 튜닝 실험 설계

2026-11-22 · 설계 단계. 기준 모델은 v2-128-A(seed 42), frontend e3·body e3·hand e2다. 아래 반복 수와 수치는 첫 비교를 위한 설계값이다. [베이스 선정 및 손목 분석](EXPERIMENT_RESULTS_REPORT.md#손목-위치와-손가락-자세-분해) · [실행기 지원 범위](V2_GPU128_A_PORTABLE_BUNDLE.md)

## 반복 수와 선택

- 기본은 학습 방식당 독립 3회, 최종 비교는 유망한 두 방식에 2회씩 추가하여 각각 총 5회다. 첫 세 seed는 42·71·103, 추가 seed는 137·181을 사용한다. 모든 방식에서 같은 seed끼리 clip 순서와 학습 noise를 맞추고 어댑터 초기화에는 별도 RNG를 사용한다. 시간 여유가 충분하고 방식이 하나면 처음부터 5회로 계획할 수 있다.
- 반복마다 같은 부모 가중치로 돌아가고 optimizer·scheduler·학습 RNG를 새로 만든다. 한 실행의 5epoch는 독립 학습 5회와 구분한다. 체크포인트 복원은 같은 반복을 이어간다. 학습률·epoch·평가 빈도는 비교 전에 고정한다.
- 공통 조건은 128 입력, 공식 train 119,586페어·3,097클립, validation 16,425페어·421클립, 평가 noise seed 71이다. 추론에는 예측 2D·예측 상체를 사용한다. FP32와 동일 GPU를 우선하고 실제 장치·캐시 준비·학습·평가·저장 시간을 따로 기록한다.
- 주 지표는 기존과 같은 세 시나리오의 body 및 hand-global MPJPE 6개 값 동일 가중 평균(mm)이다. 낮을수록 좋다. 방식 선정은 공통 seed에서 얻은 점수의 평균과 부모 대비 차이로 한다. 각 seed 값·범위·표준편차와 손목/hand-local/시나리오별 악화도 함께 공개한다. seed 3~5개로 통계적 우월성을 단정하지 않는다.
- 3회 후 평균 상위 두 방식을 남긴다. 5회의 평균이 부모보다 낮고 5회 중 3회 이상 부모 대비 개선된 방식 중 평균이 가장 낮은 것을 우선한다. 손목·hand 등 해당 분기의 목표 지표도 개선됐는지 별도로 판정한다. 종합 개선과 목표 개선을 동시에 충족하지 못하면 A를 유지한다. 선정 방식 안에서는 사전에 정한 validation 지표 최저 checkpoint를 배포 후보로 삼고 점수가 같으면 손 global macro, 다음은 작은 seed 순으로 정한다. 선택에 사용한 validation 점수와 독립 test 성능은 구분한다.

v2.1.1~.3은 직렬로 이어 학습하지 않는다. 첫 선별은 3방식 × 3회 + 2방식 × 추가 2회 = **총 13회**다. 양성 결과가 없으면 9회에서 종료할 수 있다. v2.2·v2.4는 새 부모로 바꿀 경우 부모 SHA를 새로 고정한다. 256 실험은 해상도와 부모 ID를 별도로 표시한다.

## 이후 Colab 노트북의 실행 계약

- 첫 셀에 부모 SHA, split·캐시·코드 식별값, trial 목록·학습 seed·평가 seed, 방식별 설정과 선정 기준을 표시한다. 실행 전 회차당 추정 시간, 전체 예상량, 1회 호출 상한(8시간)과 실제 승인 예산을 확인한다.
- 한 GPU에서 순차 실행한다. 각 trial의 best·last, validation 원점수와 시나리오별 집계, 학습 위치·RNG·optimizer, 로그·경과시간을 별도 경로로 Drive에 저장하고 크기와 SHA를 검증한다. 새 런타임에서는 완료 trial을 건너뛰고 중단 trial만 마지막 검증 checkpoint에서 재개한다. 미완료나 실패를 0점으로 처리하지 않는다.
- 비교 셀은 공통 seed를 모두 확보한 방식끼리 비교한다. 선별·최종 단계를 구분하고, 조건부 추가 2회는 해당 예산과 실행 선택이 있을 때 진행한다. 최종 산출물은 전체 trial 표, 방식별 평균·편차, 선정 모델/부모 SHA, 고정 예측 클립, 원래 모델과의 차이다. 기준 미달도 결과로 저장한다.
- 현재 공유본의 소규모 tune과 전체 train-full은 참고 구현이다. 전체 split에서 단계·층 선택, LoRA, 손목 손실, 수정 소스의 호환 가중치 이관, 반복 오케스트레이션은 해당 노트북 발급 전에 구현·검증한다. 이번 문서는 실험 설계이며 GPU 실행 기록은 추후 추가한다.

## 테스트 세션 인계 순서

독립 CPU 검사는 한꺼번에 인계하고 서로 다른 출력 경로에서 동시에 실행한다. GPU는 테스트 세션에 한 건씩 인계하며, 첫 작업은 학습 없는 v2.1.0 전체 validation 기준 평가다. 256 B가 실행 중이어도 별도 GPU 하나로 진행할 수 있다. 후속 노트북은 미리 제작할 수 있다. 다음 GPU 시험은 직전 결과와 선정 조건을 검토한 뒤 인계한다. 전체 예측이 필요한 CPU 집계·시각화는 해당 GPU 산출물을 받은 뒤 수행한다.

입력·기준 예측·반복 선정 검사는 [CPU 병렬 검사 가이드](V2_TUNING_CPU_HANDOFF.md), 첫 GPU 평가의 고정 입력·결과 위치는 [v2.1.0 가이드](V210_EVAL.md)에 기록한다.
