# v1·v1.1·v1.2·v1.4 종합 비교와 v1.5 제안

**2026-11-15 후속 사용자 결정:** v1.5를 카메라 표현 통제 학습 중심으로 재정의했다. 이 문서의 3~5절과 A/B/C는 **초기 설계의 보존 기록**이며 현재 주실험이 아니다. GT/예측 조건 분리는 새 v1.5의 잔여 오류에 따른 조건부 후속으로 남긴다. 별도 v1.6은 폐기했다. [최신 범위](EXPERIMENT_VERSIONS.md).

2026-11-15 번호 검토: 이 문서의 v1.5와 A/B/C는 기존 GT/예측2D·상체 조건 분리 설계를 뜻한다. v1.2.3 이후의 카메라 표현 학습과 혼용하지 않는다. 새 카메라 시험은 별도 v1.6을 제안 중이며 미확정이다. [범위 비교·버전 대응](EXPERIMENT_VERSIONS.md).

작성일: 2026-11-15. 사용자 요청에 따른 기존 근거 종합과 후속 설계다. v1.5는 제안 단계이며 구현·새 학습·사용자 시험을 시작하지 않았다. v1.1은 모델을 회수한 T4 재실행을 기준으로 하며 미회수 실행과 섞지 않는다.

## 2. 무엇을 배웠는가

- v1: teacher별20update는 실행 연결을 확인한 수준이다. 낮은 점수를 구조의 한계로 결론내릴 근거가 부족했다.
- v1.1: frontend도 함께10epoch 학습해2D는 개선됐으나 teacher별200update에서 심한 축소가 남았다. Train loss 감소와 실제 DDIM10 생성 성공은 달랐다. '학습이 아예 안 됨'이나 '과적합만이 원인'은 입증되지 않았다.
- v1.2: body 오차는169.56mm, 뼈 길이/GT는88.7%까지 개선됐다(v1.1 약6.4%). 손 뼈 길이는56.4%여서 여전히 축소됐다(v1.1 약9.0%). 데이터 폭·총update·2D 품질이 함께 개선됐기 때문에 데이터량만의 효과는 분리할 수 없다. Clip당 노출은 v1.1과 같은10회다.
- v1.4: 같은50frame을5,000번 반복하고 GT조건을 주면 몸과 손을 복원할 수 있다. 모든 입력에서 불가피하게 붕괴하는 공통 구조 결함 가설은 약해졌지만, 한클립 암기·카메라/시간 패턴 활용 가능성과 예측입력 경로의 국소 오류는 배제하지 못한다.

현재 가장 타당한 가설은 초기에 부족했던 teacher 업데이트와2D 조건 품질이 겹쳤고, 현재 손에는 상체/wrist 오류 전파와 학습·평가 조건 차이가 추가된다는 것이다. 'GT를 쓰면 성공했으니 원인은2D뿐'이라는 인과 결론은 성립하지 않는다. v1.4는 입력 외에도 반복노출·평가집합이 다르다.

최근 Getting_Up frame1/10의 시각화는 v1.2 train에 포함되고 v1/v1.1 고정1,000선택 밖이다. 모두 독립T=1이며 연속50frame 결과가 아니다. v1.2의 개선을 눈으로 확인하는 자료지만 일반화 개선의 공정한 시험은 아니다.

## 3. v1.5 권고: 예측 입력으로 단일클립 복원이 가능한가

목표는 v1.4의 oracle 성공과 v1.2의 실제 예측 사이의 간극을 줄이는 것이다. v1.2 데이터 전체 재학습이나 v1.3 시나리오 추가를 곧바로 시작하지 않는다. 먼저 작은 같은 문제에서 입력 조건과 학습·평가 불일치를 분리한다. 아래 순서를 한 고정 실험 묶음으로 준비하고 결과를 자동 회수하는 방향을 제안한다. 실제 실행본·입력 pin·예산은 구현 전 확정한다.

### 0단계: 평가 기준 정렬 — 재학습 없음

v1.4와 동일 Standing_Up train50frame에서 v1.2 best F9/B10/H9를 full temporal context로 평가한다. 기존 v1.4 GT결과와 조건 차이를 명시해 비교한다. v1.2 모델로 선택한 train클립과 사전 고정 validation클립도 같은 연속50frame 방식으로 평가해 T=1 시연과 구분한다. Validation클립은 결과를 본 뒤 고르지 않는다. 입력을 추가 확보해야 하면 규모와 비용을 먼저 고정하며, 현재 로컬2프레임만으로 이 단계가 완료됐다고 하지 않는다.

이 단계에서 이미 train은 잘 맞고 validation만 나쁘다면 아래 단일클립 학습의 우선순위를 낮추고 다중클립 일반화·입력 분포로 분기한다. Train에서도 실패하면 아래 A/B 비교를 우선한다.

### 1단계: GT2D와 예측2D의 통제 학습

v1.4의 같은50frame, 카메라, teacher 구조·loss·LR·DDIM10·precision·노이즈 일정과 update를 유지한다. v1.2 frontend best를 고정하고 예측 특징을 한 번 캐시한다. 새 frontend 학습은 하지 않는다.

| 실험 | Body의2D 조건 | Hand의2D 조건 | Hand 학습 상체 | 목적 |
| --- | --- | --- | --- | --- |
| A 대조군 | GT | GT | GT | 동일 초기화에서 oracle 재현 |
| B | 고정v1.2 예측 | 고정v1.2 예측 | GT | 2D 특징 품질의 효과 |
| C 조건부 후속 | B의 body 고정 재사용 | B와 동일 예측 | B body의 고정 예측 | Hand 학습·추론 조건 일치 효과 |

A/B의 body는 같은 초기 state를 복제하고, hand도 별도의 같은 초기 state를 복제한다. Seed 숫자만 같게 기록하는 것으로 대체하지 않는다. 과거v1.4의 최종 모델을 A 초기화로 쓰지 않는다. 모델별200/1,000/5,000update에서 동일 noise의 pure-noise DDIM10 결과를 보존하는 것을 제안한다. 최대5,000은 후보 설정이며 실제 시간·메모리 예산은 소규모 pilot 후 고정한다.

A/B는 hand를GT상체 조건에서 비교하여2D 효과를 분리하고, B를예측상체 조건으로도 평가해 입력 교체 민감도를 기록한다. GT2D와 예측2D는 confidence/presence 및 화면 밖 좌표도 달라지므로 '좌표오차만의 실험'이라고 부르지 않는다. 차이가 크면 좌표/신뢰도 분리 실험은 별도 후속으로 설계한다.

### 2단계: 필요한 경우에만 C

A/B에서 예측2D 조건으로 body가 복원되고, hand가GT상체에서 잘 맞지만예측상체에서 악화된다면 C를 수행한다. B의 최종 body를 고정해 같은 클립의 상체/wrist 예측을 캐시한다. C의 hand는 B hand와 동일한 초기 state·update·noise·설정을 사용하고, 학습 상체만 캐시된 예측으로 바꾼다. B/C 평가는 동일한 B body 예측으로 한다. C가 GT를 입력받지 않는다고 GT 손의 지도 학습까지 제거하는 것은 아니다.

v1.2 best hand를 그대로 추론하면서 GT상체로 교체하는 검사는 추가 학습 없이 가능한 민감도 검사이지만, 분포가 바뀐 입력에 대한 결과다. 그것만으로 예측상체 학습의 효과를 입증하지 않는다. C에서는 손을GT/예측wrist에 붙인 global오차를 각각 기록하고 local오차도 분리한다. Global-local 차이를 wrist오차로 단순 차감하지 않는다.

## 4. 판정과 이후 방향

| 관찰 | 후속 판단 |
| --- | --- |
| A도 과거v1.4 수준으로 복원되지 않음 | 입력·초기화·조건·좌표·샘플러 재현부터 확인, C/대규모 실행 중단 |
| A는 성공, B가 크게 악화 | frontend특징 품질/정보 이용·조건인코딩을 우선 조사 |
| B hand는GT상체에서만 성공, C에서 예측상체 성능 개선 | hand 조건 불일치가 기여한다는 근거; 이후ArchVis에같은변경을한번만적용 |
| B/C train은 성공하지만 validation에서 악화 | 단일클립 암기의 한계; 고정 다중클립에서 일반화 검증 |
| 충분한학습으로도 예측입력train이붕괴 | 조건별gradient·loss/sampling·좌표/mask 국소구현 검토; 무조건epoch확대하지않음 |

성공 기준은 단순loss감소가 아니다. Body22관절 MPJPE, hand40관절 local/global, bone/spread비율, frame별오차·첫/중간/끝동작, 평균자세baseline과의차이, GT/예측overlay를 함께 기록한다. 동일 noise 비교를 주 판정으로 하고 사전 고정한 추가seed에서 결과 안정성도 확인한다. A의 재현 허용치와 B/C의 개선 판정치는 실행 전에 수치로 고정해야 하며 이번 문서에서 임의로 통과 판정을 만들지 않는다. 여러후보를validation으로고르면 해당집합은개발용평가임을유지하고test는쓰지않는다.

단일클립 성공은 미니 데모의 복원 가능성이지 범용 모델 완성이 아니다. v1.5에서 확인된 변경만 v1.2 데이터에 적용하는 후속을 제안하며 v1.3은 계속 보류한다.

## 5. 비용과 운영

신규데이터확대없이 한클립 RGB·pose/특징 캐시를 재사용한다. A/B는body2개·hand2개, C까지하면body2개·hand3개의독립학습이므로 v1.4 한실행10분을 그대로 v1.5 전체예산으로 인용하지 않는다. 반복입력준비와frontend재학습을줄일수있지만 실제GPU·준비/추론/학습/보관 시간을pilot에서따로측정한다. 지원CUDA GPU를허용하고A100을강제하지않는다.

진단·조건부학습·저장·시각화를고정실행본에묶어중간수동질문을줄이는방향이다. 실패/NaN/identity불일치/상한도달시보고서를자동보관하고중단하며예산을자동확대하지않는다. 비용·중단기준·분기조건을사전에확정하기전에는자동실행하지않는다. 결과/checkpoint는Drive보관,캐시업로드는사용자담당규칙을유지한다.
