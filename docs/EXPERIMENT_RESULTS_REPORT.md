# REWIND-like prototype 실험 결과 종합 보고서

최종 갱신 2026-11-22 · 128 전체 캐시 완료·256 캐시 907샤드 보관 · 모델 결과 v0~v1.5.3 · v2 CPU 캐시 첫 샤드 보관 확인, A100 첫 샤드 복원 통과 · 새 CPU VM 재개 및 A100 경계 배치 통과 · 남은 캐싱 예산 확정

이 문서는 프로젝트의 실험 결과를 읽는 기본 진입점이다. 개별 보고서의 결과·검토 범위를 종합하며, 새 테스트 설계와 결과 검토 때 계속 갱신한다. 이번 작성은 기존 근거의 통합이며 새로운 학습·GPU 실행이나 원본 결과 전체의 재검증을 뜻하지 않는다.

2026-11-18 후속 승인: v2 통합 학습 준비를 진행한다. 아래 v1.3 보류·새 실행 미승인 표현은 이전 결과 검토 시점의 기록이며, v1.3은 v2로 이관한다. v2 실제 학습 결과는 아직 없다. 후속 승인으로 입력 준비·학습 각1회8시간을 확정해 전용 보존·재개 인프라 구현·신규14검사와 root 검토를 완료하고 고정본 발급 대기 중이다. 누적 예산·학습 선택·실제 v2 GPU 실행은 미확정/미실행이다. [범위·확정 시간 계약](V2_PLAN.md).

## 1. 현재 결론

**학습·평가·모델 저장 경로는 동작하며 몸 형태 복원도 개선됐다. 그러나 손 축소와 자세 오류가 남아 있어 정확한 REWIND-like 시연 모델이 완성된 상태는 아니다.**

1. 초기 1,000페어 학습에서는 2D가 중앙에 몰리고 3D가 축소됐다. 같은 규모에서 epoch를 늘린 v1.1도 이를 충분히 해결하지 못했다.
2. v1.4는 한 클립에 GT 2D·hand용 GT 상체를 제공하고 충분히 반복 학습하면 몸과 손 형태를 복원할 수 있음을 보였다. 이는 실제 RGB 추론이나 일반화 성공과 다르다.
3. v1.2는 ArchVis 전체 학습으로 2D·몸 복원이 개선됐지만, CityPark·Downtown에서는 큰 위치 오류와 축소를 보였다.
4. 대조·원점 개입 시험에서 카메라의 절대 world 원점 의존성을 확인했다. v1.5의 통제 학습에서는 첫 프레임 stereo 중점 표현이 이 민감도와 도시 표본 오류를 줄였다.
5. 중점 모델도 손 뼈 길이가 GT의 약34.6%에 머문다. v1.5.1에서 GT 상체로 local 오차는10.8% 줄었지만 뼈 길이는GT의약33.7%로 축소가 남았다. 상체 오류만으로 손 실패를 설명할 수 없다.

6. v1.5.3에서는 예측2D 특징·GT 상체로 한 클립을 충분히 반복해 body10.78mm·hand5.65mm와 형태 복원을 확인했다. 단일클립 학습 가능성의 근거이며 다중클립 일반화는 미확인이다.

위 결론은 정해진 표본·조건의 근거다. 논문 성능 재현, 다양한 인물·동작의 독립 일반화, 완결된 RGB-only 추론, 실시간 영상 시연을 입증한 것은 아니다.

```text

└─ v1 — 1,000페어 REWIND 기반 frontend/body/hand 각1epoch
   ├─ v1.1 — 같은 규모 각10epoch [완료, 3D 축소 잔존]
   │  └─ v1.4 — 단일 train 클립 GT 조건 과적합 [완료, 형태 복원]
   ├─ v1.2 — ArchVis train20,888페어 각10epoch [완료]
   │  └─ v1.2.1 — CityPark·Downtown 무재학습 추론 [완료, 실패 관찰]
   │     └─ v1.2.2 — ArchVis 대조·카메라 분포 비교 [완료]
   │        └─ v1.2.3 — 동일 장면의 world 원점 개입 [완료]
   │           └─ v1.5 — 카메라 표현 통제 학습 [완료, 손 오류 잔존]
   │              ├─ v1.5.1 — 고정 중점 모델 GT/예측 상체 비교
   │              │           [T4 결과 검토 완료, local 일부 개선·손 축소 잔존]
   │              ├─ v1.5.2 — 저장 모델 복원·생성 진단 [T4 결과 검토, 손 축소·재현 확인 과제 잔존]
   │              └─ v1.5.3 — 예측2D 단일클립 학습 [T4 각5,000update 완료, 형태 복원·일반화 미검증]
   └─ v1.3 — 다른 시나리오 혼합 학습 [v2로 확대·이관]
      └─ v2 — 세 시나리오 전체 train 통합 학습 [준비 승인·학습 미시작]
         └─ CPU 캐시 128페어 [보관 확인] → 동일 샤드 A100 한 배치 읽기 [통과] → 정식 복원 및 한 배치 읽기 [Colab 통과]
            └─ 다중 샤드 CPU 캐싱 → 재개 → GPU 경계 배치 [4샤드·512프레임, Colab 통과]
               ├─ 전체 manifest 128 캐싱 [1,063샤드·136,011페어 완료]
               └─ 128·256 동일 표본 비교 [384페어 완료, 256 ZIP 3.983배]
                  └─ 256 운영 캐시 [907샤드·116,096페어 보관 → 나머지 156샤드 재개]

v1.6 — 별도 버전 폐기; 유효한 제안은 재정의된 v1.5에 흡수
```

화살표는 질문과 실험 설계의 계보다. 같은 checkpoint를 이어 학습했다는 뜻은 아니다. 초기 v1.5 단일클립 A/B/C 제안은 현재 실행된 v1.5와 다르며 역사로 보존한다. 상세 결정은 [실험 계보](V1_EXPERIMENT_LINEAGE.md), 이름과 실행 ID 대응은 [버전 관리](EXPERIMENT_VERSIONS.md)를 따른다.

## 4. v1.4: 정답 조건에서 학습할 수 있는가

같은 train 클립50프레임, GT 2D와 hand용 GT 상체, body/hand 각각5,000update의 진단이다. Body에 GT 3D 상체를 입력한 것은 아니다.

| Update / 모델 | Body mm | Hand local mm |
| --- | ---: | ---: |
| 0 |495.39|143.02|
| 200 |123.19|47.03|
| 1,000 |19.19|10.82|

## 10. 계속 갱신하는 방식

- 새 테스트를 설계하거나 결과를 검토할 때 이 문서의 상단 날짜·상태·트리·표·결론·다음 작업·보존 경로를 함께 갱신한다. 아직 회수되지 않은 결과는 대기로 둔다.
- 전용 결과 보고서에는 원본 수치·설정·revision·SHA·검증 근거를 보존한다. 이 문서는 종합 판단의 진입점, `V1_EXPERIMENT_LINEAGE.md`는 날짜별 분기·판정 이력으로 유지한다.
- 관찰과 원인 가설, 로컬 검증과 실제 GPU 결과, GT 진단과 배포 입력 결과를 구분한다. 다른 평가 조건의 숫자를 같은 성능 순위로 합치지 않는다.
- 판단이 바뀌면 새 근거와 변경 이유를 아래 이력에 남긴다. 과거 개별 보고서의 당시 판단을 근거 없이 덮어쓰지 않는다.
- 결과 검토 시 갱신하는 운영 규칙이며 별도 백그라운드 감시나 새 실행 승인을 의미하지 않는다.
