## 이전 자료의 아카이브

이번 보관 위치는 프로젝트 루트 기준 다음과 같다.

- `.local-archive/20261023/legacy_outputs.zip`: 현재 테스트에서 사용하지 않는 이전 실행의 보고서·로그·스크립트·고정 배포본 등 보존 가치가 있는 자료.
- `.local-archive/20261023/INDEX.json`: 보관 파일의 원래 경로, 바이트 수, SHA256, ZIP 내부 위치와 복원 위치를 확인하는 인덱스.
- `outputs/cleanup_20261023/inventory_before.json`: 정리 전 파일 목록과 용량. 최종 보존·보관·삭제 내역 및 검증 결과는 같은 정리 폴더에 기록한다.

ZIP 내부에는 `outputs/...`로 시작하는 원래 상대 경로를 유지한다. 예전 문서에 적힌 `outputs/...` 링크가 로컬에서 열리지 않으면 인덱스에서 보관 여부를 찾고, 필요한 파일을 원래 경로로 복원할 수 있다. 문서의 과거 경로를 현재 테스트의 다른 파일로 바꾸어 연결하지 않는다.

아카이브 작성 후 ZIP을 실제로 읽어 각 파일의 크기와 SHA256을 원본 및 인덱스와 대조하고 ZIP 검사를 수행한다. 검증이 끝난 파일만 기존 작업 위치에서 제거한다. 실패하거나 현재 테스트와의 참조가 불명확한 파일은 보존한다. ZIP 형식의 무결성 검사는 보관된 실험 결과의 타당성이나 원본 데이터 전체의 무결성을 뜻하지 않는다.

`.gitignore`의 `/.local-archive/`와 기존 `/outputs/` 규칙으로 두 위치를 Git에서 제외한다. 강제 추가하지 않으며 소스 배포 ZIP에도 대형 아카이브를 포함하지 않는다. 로컬 아카이브는 같은 디스크에 있으므로 별도 영구 백업 여부는 따로 확인한다.

## 재생성 가능한 파일의 정리

`outputs/uv_cache/`는 패키지 설치 캐시로 분류해 정리할 수 있다. 설치된 `.venv/`는 유지하며, 캐시를 지운 뒤 환경 재구축 시 패키지 재다운로드가 필요할 수 있다.

이전 warm128 검증에서 만든 대형 합성 fixture·중복 추출본은 실제 캐시와 구분한다. 현재 테스트의 참조가 없는 재생성 가능한 파일만 삭제하고, 재현에 필요한 스크립트·설정·로그·hash는 보관한다. 삭제 대상과 근거를 정리 기록에 남긴다. 실제 데이터·사용자 결과·실제 prefix 캐시를 합성 임시 파일로 취급하지 않는다.

## 개별 파일 복원

1. `INDEX.json`에서 필요한 파일의 원래 상대 경로, ZIP 내부 위치, 크기와 SHA256을 확인한다. 아카이브 자체의 검증 기록도 확인한다.
2. 필요한 개별 파일만 선택한다. ZIP 멤버 경로에 절대 경로·상위 경로 이동·링크가 없는지 확인하고, 최종 대상이 현재 프로젝트 폴더 내부에 있는지 확인한다.
3. 원래 위치에 파일이 이미 있으면 덮어쓰지 않는다. 같은 파일이면 크기·hash를 비교하고 기존 파일을 유지한다. 다르면 프로젝트 내부의 별도 빈 복원 폴더에 저장해 비교한다.
4. 선택한 파일을 복원한 뒤 크기와 SHA256을 인덱스와 대조한다. 원래 위치로 복원하면 해당 과거 문서 링크를 다시 사용할 수 있다. 일부 파일만 복원했다면 실행에 필요한 다른 파일도 인덱스에서 확인한다.

이번 정리는 파일 보관 위치와 용량을 정리하는 작업이다. 모델·학습 설정·테스트 입력·실험 상태는 변경하지 않는다. 추가 학습이나 사용자 테스트를 실행하지 않으며, 검토와 로컬 커밋은 오케스트레이션이 담당한다.
